# Nightly-curator evaluation evidence (issue #377)

This directory holds the machine-readable go/no-go evidence for the opt-in model
curator evaluation. The harness lives in `tests/support/nightly_curator/`.

## Reproduction

```bash
# the eight frozen contract specs (pytest; the same functions run under plain
# `python tests/test_nightly_curator_contract.py`, which is the CI shape)
python -X utf8 -m pytest --disable-plugin-autoload --noconftest -p no:cacheprovider -q \
  tests/test_nightly_curator_contract.py

# regenerate the committed decision report at the current HEAD
python tests/support/nightly_curator/evidence_run.py

# the shadow prototype's executable install/disable surface (scratch dir only)
python tests/support/nightly_curator/orchestration.py enable  <scratch-cfg-dir>
python tests/support/nightly_curator/orchestration.py dry-run  <scratch-cfg-dir>
python tests/support/nightly_curator/orchestration.py disable <scratch-cfg-dir>
```

A regeneration whose canonical digest matches the committed one proves the
artifact is reproducible (telemetry values may differ; the canonical digest
excludes them by design).

## Evidence run contents

`decision-report.json` is generated by the committed generator
(`tests/support/nightly_curator/evidence_run.py`) at the `source_sha` recorded
inside it, with:

- `deterministic-zmem` — executed (real `store.py` CLI on isolated scratch stores,
  `ZMEM_EMBED_PROFILE=fake`, the same deterministic profile the eval fixtures use).
- `lexical-baseline` — executed (no-model variant).
- `deepseek-scripted` — `excluded_fixture_only` (never a model-quality candidate).
- `local-endpoint` — `unavailable` (no loopback endpoint configured).
- `tencent` — `unavailable` (no endpoint configured anywhere in-repo).
- `general` (claude-cli) — `unavailable` BY CONSTRUCTION: the harness's hermetic
  child env (scratch HOME/USERPROFILE, no credential channel) withholds host
  credentials by design, so the CLI cannot authenticate inside the harness
  (recorded CLI error: `Not logged in`). Logging in on the host cannot change
  this; measuring this leg would require a deliberately-designed credential
  channel that only opens under transmission consent — future work, tracked in
  the PR discussion.

## Judge method (disclosed)

The review-claim judge is `keyword-rule-v1` — a deterministic keyword rule
(recorded in `rubric.metrics.judge_method` and in the spec file). It is NOT a
model; its agreement with the model-lane verdicts of record is reported as
`judge_vs_model_reviewed` per case.

## Reading the report

- Two digests: `canonical_decision_digest` (telemetry-free; stable across
  re-runs) and `raw_artifact_digest` (immutable, telemetry included).
- `go_no_go.model_go` is false while no executed MODEL-BACKED writer exists;
  unavailable inference yields no score and can never produce a model GO.
- `maintainer_evidence_pending` lists the AC2 judge/human-disagreement evidence
  gap: the fixture (`tests/fixtures/nightly_curator/reviewed_histories.json`)
  carries model-attributed verdicts of record (never human; the 16 cases come
  from four review comments, not 16 independent histories — see its
  `harvest_rule`); the metric computes only over per-case `human_endorsement`
  rows, which are empty until the owner annotates or amends the contract (asked
  twice 2026-11-14, no answer — see the PR body).
- The plan-critic's six-round review trail and the interim-contract boundaries
  are in the PR description.
